===== CONTROL 4  =====
Goals of an AI-First and Agentic Development Process
To accelerate the rate at which we can deliver functional and quality code, we want to employ an approach to code generation that is:
AI-First
and   Agentic
In addition, the goal of an AI-First SDLC is to incorporate AI into every facet of the software development process:
Category    Area    Description
Design    AI-First Planning and Design   Leverage AI for architecture recommendations, requirements gathering, feature/story refinement, and backlog grooming before coding begins to optimize resources and reduce rework.
AI-Powered Database Design and Optimization   Use AI for schema design, DML generation, and query optimization for efficiency and accuracy in data handling.
Code Development    AI-Driven Code Changes Across All Development Types   AI used for feature development, bug fixes, spikes/research and maintenance tasks
High Percentage of AI-Generated New Code   Maximize the % of code written by AI to increase efficiency and allow developers to focus on higher-value activities.
AI-Enabled Maintenance and Refactoring   Automate maintenance tasks using AI to reduce technical debt and improve long-term sustainability.
AI-Assisted Code Reviews at All Stages   Implement AI-powered reviews locally and during pull requests to enforce standards and catch issues early.
AI-Powered Security Validation   Use AI for vulnerability scanning, compliance checks, and secure coding practices to mitigate risks and meet industry standards.
Automated Code Documentation via AI   Ensure comprehensive and accurate code documentation is generated by AI for consistency and reduced manual overhead.
Testing/Validation    Comprehensive Test Coverage with AI-Generated Cases   Achieve near 100% test coverage, with test cases generated by AI. This ensures reliability, reduces defects, and accelerates QA cycles.
AI Validation Against Acceptance Criteria   Automate validation to ensure code meets business requirements and reduce cycle time.
AI-Driven Performance Testing   Apply AI to simulate workloads, predict bottlenecks, and optimize performance under varying conditions.
Infrastructure/Observability    AI-Generated Infrastructure as Code (IaC)   Use AI to create and manage IaC (DAPS) for faster provisioning and reduced configuration drift.
AI-Generated Observability and Monitoring Queries   Use AI to create queries and dashboards for proactive monitoring and incident management.
Why Agentic?
Multi-step coding tasks become more seamless via specifications given to the agent
Greater control over the structure and quality of the code via agent instructions
Can incorporate all aspects of the cycle into a change:  Tests, code, local execution, review
Naturally enhances documentation of requirements
To effectively accomplish this, we need a process that is optimized for agents:
The best tools AI models for interacting with agents
Agents should clearly understand  what  to solve for each feature regardless of the technical implementation
Agents must know  how  to go about solving it, what  rules  apply, and how it should  organize  the work
Generated code must be secure, maintainable, performant and follow standards
We must have a way to measure, observe and validate AI-generated code.

===== CONTROL 16 Step 2:  Using a Spec-Driven Development Flow and Context Engineering =====
The Specification-Driven Agentic Flow
By first creating specifications for the agent to follow and storing them as physical files in your codebase, a  spec-driven  flow enables agents to work  iteratively  with less hand-holding:
Create product spec:   Tell the agent how your  codebase  is organized (product/codebase specs)
Create feature spec:   Give a clear description of each  feature / business process  to build (feature specification)
Create technical spec:   Have the agent provide a plan for how to  technically implement  it (technical specification)
Have the agent provide a  task list  to work from in small increments (it is optimized for small, iterative tasks)
Execute  the tasks and review along the way

2. /create-spec:   Create Feature + Technical Specifications
Using the   /create-spec   command (Agent OS) or Plan mode (Claude Code), ask the agent to create a detailed specification document for each new feature.
VS Code :
Type  /create-spec  followed by a description of the feature you want to create.  Add detailed information about the purpose of the feature, business logic and high-level implementation details.
Visual Studio :
Type  #prompt:  and then select  created-spec.prompt.md.   Then type a description of the feature you want to create.  Add detailed information about the purpose of the feature, business logic and high-level implementation details.
The agent should then generate a set of markdown files in your .agent-os/specs directory with detailed requirements
Feature spec documents are focused on just the problem to be solved and are different from technical implementation specs.
Include information about key aspects such as user interaction, security requirements, key endpoints to be leveraged, tech stack requirements, how to break down the code modules, etc.
Leverage details from PBIs to enhance the spec creation process.
Ask AI to optimize your initial prompt for use with the coding agent.
Review each specification document and ask the agent for modifications where needed.  Iterate on the document to ensure it aligns with the goal and that the solution is not overly complex.
A few things to look for:
Redundant code â€“ does the plan create redundant functionality?
Reusability â€“ is the plan creating shared services that are too specific?
Is the solution overly complex?  Is there a simpler way to approach the problem?
3. Create the task list  - a granular set of sequential tasks the agent should follow to build the feature
With the spec open in your editor, ask the agent to create a task breakdown for executing the plan.  Review the plan prior to any code generation.
The agent should then create a detailed breakdown of tasks for it to follow within a  tasks.md  file
A granular set of tasks will allow the agent to efficiently deliver increments that require less context.  It also allows for breakpoints for you to review the code for issues before it gets too far along.
Ensure the plan follows key development principles:
Individual tasks should be limited in scope and avoid broad changes at once
Creation of tests is part of the plan
Security logic is being considered
There are clear breakpoints in the task list where the feature could be partially tested
Use history effectively
Track what the agent does by having it record progress in the task list.  Have it clearly note any issues along the way and donâ€™t let it skip too many steps.  It can be less rework to have it iteratively solve a step than skip it.
Manage your conversations effectively.  Donâ€™t always start multiple new features in a single conversation flow.  It is often better to start fresh chats for new features.
Also make sure to prompt effectively based on the history.  A new chat will not have all the context related to what you were just asking the agent to do previously.
Detailed Context Engineering guidance:   Context Engineering.loop

===== CONTROL 19  =====
Drive quality with constant review and feedback
Ask the agent to  check for errors  often before continuing
Review  all new  libraries  added by the agent during code generation.  Ensure the agent asks for human confirmation before running any package install command.  Allowing the agent to add new libraries shouldnâ€™t be a frequent activity.
Always  validate packages  the agent adds are free from restrictive licensing and that versions are not outdated.  (link to acceptable licenses TBD)
Ensure thorough  code reviews  to capture mistakes or security issues
Donâ€™t let the agent do  too much work at once
Commit often  to your local branch to limit the scope of reverts.  The agent may sometimes need to restore a file from your git history.
Coding agents tend to generate verbose and sometimes overly complex code.   Review frequently  and ask it to refactor along the way where needed.
Continuously update  the project instruction/context files to document new features/patterns.
Stop the agent early if standards arenâ€™t being followed and ask it to revise the plan
Ask the agent to generate code comments in areas of complexity
Additional Guidelines
Never include customer data, PII or secrets/credentials in prompts
Take extra care with agent-generated code that affects IaaC/resource provisioning, critical security code or logic dealing with PII
Ensure there is proper code coverage and automated testing of AI-generated code
Engineers are ultimately responsible for code they accept from agents.  All agent-created or modified content must follow the same code review, testing, and security policies as human-written code.
Complex feature changes should still go through normal design and architectural review.  Agent plans and code are an input, not a replacement.
